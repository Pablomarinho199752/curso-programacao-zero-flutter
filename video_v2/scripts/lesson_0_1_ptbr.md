# Aula 0.1 — Primeiros passos: pensar, testar e corrigir

## Narração

Antes de aprender comandos, existe uma ideia mais importante: programar é aprender a dar instruções claras. O computador não adivinha o que você quis dizer. Ele executa exatamente o que foi escrito. Por isso, nesta primeira aula, o objetivo não é decorar Python. É começar a pensar como alguém que programa.

Imagine um robô diante de uma mesa. Na mesa há um copo vazio e uma jarra aberta com água. Se você disser apenas “coloque água no copo”, talvez uma pessoa entenda. Mas um robô precisa de passos. Segure a jarra. Levante a jarra. Posicione o bico sobre o copo. Incline devagar. Pare quando o copo atingir a quantidade desejada. Volte a jarra para a posição vertical e coloque-a na mesa.

Essa sequência organizada de passos é um algoritmo. Um algoritmo é o plano para resolver uma tarefa. Quando pegamos esse plano e escrevemos em uma linguagem que o computador entende, como Python, temos código. E um programa é um conjunto de instruções que pode ser executado.

Vamos ver nosso primeiro comando. Escrevemos print, abrimos parênteses, abrimos aspas, escrevemos Olá, fechamos aspas e fechamos parênteses. O print pede ao Python para mostrar alguma coisa na saída. As aspas dizem que aquilo é um texto. E os parênteses envolvem o que será mostrado.

Um detalhe importante: na saída aparece Olá, sem aspas, sem print e sem parênteses. O código é uma coisa. O resultado mostrado pelo programa é outra.

Agora observe duas instruções. Primeiro: print “Olá, mundo!”. Depois: print “Um passo de cada vez”. O Python executa de cima para baixo. Então a primeira frase aparece antes da segunda. O significado das palavras não muda a ordem. A ordem é definida pelas instruções.

Antes de executar qualquer código, crie o hábito de prever o resultado. Olhe para print “Estou aprendendo Python”. O que você espera ver? Apenas: Estou aprendendo Python. Depois execute e compare. Se a saída for igual ao que você previu, ótimo. Se não for, existe alguma diferença para investigar.

E quando aparece um erro? O objetivo não é apagar tudo e começar de novo. Leia a mensagem. Veja qual linha foi indicada. Compare a estrutura com um exemplo que funciona. Depois altere uma coisa de cada vez.

Imagine este código: na primeira linha, print “Consegui começar” com tudo fechado corretamente. Na segunda, print “Vou testar de novo”, mas falta o parêntese final. O Python reclama porque algo que foi aberto não foi fechado. A correção não exige trocar o programa inteiro. Basta encontrar o detalhe e fechar o parêntese.

Esse processo vai aparecer durante todo o curso: prever, executar, comparar e corrigir. Errar faz parte da programação. O importante é transformar o erro em uma pista.

Agora vem uma pequena prática. Pense novamente no robô, no copo e na jarra. Escreva de quatro a seis passos claros. Pergunte a si mesmo: meu robô saberia qual objeto pegar? Saberá quando parar de despejar? Saberá onde deixar a jarra depois? Se alguma dessas respostas for não, seu algoritmo ainda pode ficar mais claro.

Para terminar, crie seu primeiro mini projeto. Faça um cartão de apresentação com duas linhas usando print. Na primeira, coloque um apelido. Na segunda, escreva algo que você gostaria de criar com programação. Não precisa usar seu nome real. Antes de executar, preveja a ordem das duas linhas. Depois rode o código e confira.

Se você entendeu que algoritmo é o plano, código é o plano escrito em uma linguagem e que programar envolve prever, testar e corrigir, você já começou do jeito certo. O objetivo daqui para frente não será copiar comandos. Será entender o que cada instrução faz e por que o resultado aconteceu.
